# Seeker DevToolbox 技术选型与架构方案

> 状态:讨论稿 v0.1 · 2026-10-25
> 实施状态:M0 骨架 + JSON 垂直切片已完成,免安装包与脚本见 [README](../README.md)。
> 定位:Windows 平台「开发者综合工具箱」,传统主窗口形态,免安装绿色分发。

---

## 1. 结论

**推荐:.NET 10 (LTS) + WPF + WPF-UI + CommunityToolkit.Mvvm,自包含发布;主产物为「解压即用」的绿色目录,附带可选单文件 exe。**

选它的核心理由:

1. 你选的是 C#/.NET,而 WPF 是 .NET 桌面上**控件生态最成熟**的 UI 框架——代码编辑器、Diff、语法高亮、图表都有现成轮子,做开发者工具正好。
2. 免安装最容易做干净:自包含发布后目标机**不需要装任何运行时**,不写注册表、不写 Program Files,删目录即卸载。
3. 体积不是你的约束(功能优先),因此可以完全接受 WPF 自包含包 150MB 左右的代价,换取开发效率和稳定性。
4. WinUI 3 的「非打包(unpackaged)」部署坑较多;Avalonia 更现代但生态偏小。两者都作为备选保留(见 §3)。

主要代价:

- WPF **不支持 trimming / NativeAOT**,自包含体积下不去(约 130–180MB)。
- 单文件 exe 首次启动需要解压原生库到 `%TEMP%`,会比目录版慢 1–2 秒。
- 默认观感偏旧,但 .NET 9/10 已内置 Fluent 主题、WPF-UI 可补齐 WinUI 风格控件,能做到接近 Win11 原生观感(见 §4.1)。

## 3. 候选方案对比

评分 5 = 最符合本项目。

| 维度 | WPF | WinUI 3 | Avalonia 11 | Tauri 2 | Electron |
|---|---|---|---|---|---|
| 语言/技能匹配 | **5** | 4 | 4 | 2 | 3 |
| 免安装友好度 | **5** | 2 | **5** | 4 | 3 |
| 自包含体积 | 2 | 3 | 4 | **5** | 1 |
| 冷启动 | 3 | 3 | 4 | **4** | 2 |
| UI 现代感 | 3(配 WPF-UI 可达 4) | **5** | 4 | **5** | **5** |
| Windows 深度集成 | **5** | **5** | 4 | 3 | 3 |
| 控件/生态 | **5** | 3 | 3 | 4 | **5** |
| 综合 | **推荐** | 不推荐 | 备选 | 不适用 | 不推荐 |

**逐个说明:**

- **WinUI 3**:UI 最现代,但非打包应用要自带 Windows App SDK 运行时引导,单文件/绿色化很折腾;部分能力(如通知、更新)默认依赖 MSIX。对「免安装」是逆风局,排除。
- **Avalonia 11**:C# 写 UI,支持 NativeAOT,体积可做到 40–60MB、启动更快,跨平台。缺点是第三方控件和中文资料少于 WPF,做编辑器类工具要自己补一些轮子。**如果后面更在意体积或 Mac/Linux,这是首选迁移目标。**
- **Tauri / Electron**:需要前端技术栈,与你的 C# 技能不匹配;Electron 体积 150MB+ 且启动慢,没有优势。
- **Rust + egui/Slint**:体积和启动最优,但 UI 开发效率低、中文输入法/字体要额外处理,不适合快速堆功能。

> 结论:当前约束下 WPF 的综合收益最高。生态是工具箱类产品最关键的变量。

## 4. 推荐技术栈清单

| 领域 | 选型 | 说明 |
|---|---|---|
| 运行时 | .NET 10 LTS | 2025-11 发布,支持到 2028-11;若公司环境受限可降到 .NET 8 LTS |
| UI 框架 | WPF (`net10.0-windows`) | Windows 专属,无 WebView 依赖,可完全离线 |
| UI 组件库 | **WPF-UI 4.x** | Fluent 风格控件、Mica/亚克力、图标;备选 HandyControl / MaterialDesignInXaml |
| MVVM | CommunityToolkit.Mvvm 8.x | 源生成器,`[ObservableProperty]` / `[RelayCommand]`,样板代码少 |
| 依赖注入 / 宿主 | Microsoft.Extensions.Hosting + DI | 统一配置、日志、生命周期 |
| 配置持久化 | System.Text.Json → `data/settings.json` | 不上注册表,便携可带走 |
| 日志 | Serilog + File sink | 按天滚动,写 `data/logs/`,崩溃可追溯 |
| 代码编辑器 | ICSharpCode.AvalonEdit | JSON/XML/正则高亮、行号、折叠、大文本虚拟化 |
| 文本 Diff | DiffPlex | 轻量,行内/行级 diff 都支持 |
| 单实例 | 命名 Mutex + 命名管道 | 第二次启动唤起已有窗口并传参 |
| 测试 | xUnit(内置断言) | 只测 Core 纯逻辑,UI 不写单测 |
| 打包 | `dotnet publish` + PowerShell 脚本 | 产出 zip 与单文件 exe |
| 自动更新 | 暂不做(Velopack 可选) | 绿色版更新用「覆盖解压」即可;后续再评估 |

## 4.1 WPF 现代化:能到什么程度

先说结论:**2026 年的 WPF 已经不是「WinForms 换皮」**。分三层做,可以做到接近 Win11 原生工具的观感;但做不到 WinUI 3 的像素级一致和合成动画。

### 第一层:框架原生(.NET 9 / 10)

- .NET 9 起 WPF **内置 Fluent 主题**,一个属性即可开启,并支持跟随系统明暗切换。
- .NET 10 补齐了 `TextBox`、`RichTextBox`、`DatePicker`、`GroupBox`、`GridSplitter`、`Label`、`Hyperlink`、`GridView` 等控件样式,修了 `Expander` 动画;官方说明「Fluent 样式支持仍在完善中」。
- 优点:零第三方依赖,系统控件行为一致;缺点:控件覆盖不全,导航、`InfoBar`、面包屑这类没有。

```xml
<!-- App.xaml:全局跟随系统 -->
<Application x:Class="Seeker.DevToolbox.App.App"
             ThemeMode="System"
             ...>
```

```xml
<!-- 也可以按窗口单独指定 -->
<Window ThemeMode="Dark" ... />
```

### 第二层:组件库补齐(推荐 WPF-UI)

- **WPF-UI(lepoco)** 是目前最贴合 Fluent 的 WPF 组件库(约 9k stars),提供:
  - `FluentWindow`:`Mica` / `Tabbed` 背景、Win11 圆角、Snap Layouts、自定义标题栏
  - `NavigationView`、`TitleBar`、`Snackbar`、`InfoBar`、`Dialog`、`NumberBox`、`BreadcrumbBar`、`SymbolIcon`
  - 基础控件全部 Fluent 化(按钮、输入框、列表、开关、进度条…)
- 正好匹配「左侧导航 + 右侧内容页」的工具箱结构。
- 备选:`HandyControl`(控件多,风格偏 Material)、`MaterialDesignInXaml`(生态大但非 Fluent)、`ModernWpf`(已停更,不建议)。
- **注意**:WPF-UI 的样式与 .NET 内置 Fluent 主题**二选一**,不要混用,否则控件模板会互相覆盖。建议以 WPF-UI 为主,内置主题只用来兜底系统级控件。

### 第三层:自己补细节

| 项 | 做法 |
|---|---|
| 自定义标题栏 | 扩展内容到标题栏,处理拖动、双击最大化、右键系统菜单、Snap Layouts 命中区 |
| Win11 圆角 | `DwmSetWindowAttribute(hwnd, DWMWA_WINDOW_CORNER_PREFERENCE, ...)` |
| Mica / 亚克力 | WPF-UI 的 `WindowBackdropType`;Win10 无 Mica,自动降级为纯色,别指望模糊 |
| 字体 | `Segoe UI Variable`(回退 `Segoe UI`),正文 14px,标题 20/28px |
| 图标 | `Segoe Fluent Icons` 或 Fluent System Icons,统一 16/20/24 三档 |
| 设计 token | 4/8px 间距栅格、4/8px 圆角、系统强调色,集中放 `Theme/` 资源字典 |
| 动效 | 只做 150–200ms 的淡入/位移;页面切换、Snackbar、骨架加载三类即可 |
| 深色优先 | 开发者工具多在暗色环境使用,首版就以深色为默认做设计 |

### 代码骨架

```xml
<ui:FluentWindow x:Class="Seeker.DevToolbox.App.MainWindow"
                 ExtendsContentIntoTitleBar="True"
                 WindowBackdropType="Mica"
                 WindowCornerPreference="Round">
    <Grid>
        <Grid.RowDefinitions>
            <RowDefinition Height="Auto" />
            <RowDefinition Height="*" />
        </Grid.RowDefinitions>

        <ui:TitleBar Grid.Row="0" Title="Seeker DevToolbox" />

        <ui:NavigationView Grid.Row="1" ... />
    </Grid>
</ui:FluentWindow>
```

### 天花板:要有合理预期

| 能力 | WPF(+WPF-UI) | WinUI 3 |
|---|---|---|
| Mica / Acrylic | Win11 可以,Win10 降级 | 原生 |
| 圆角 / 阴影 / 强调色 | 可以 | 原生 |
| 与系统设置页一致 | 接近(约 90%) | 完全一致 |
| 复杂动画 / 合成效果 | 弱(无 Composition API) | 强 |
| 控件齐全度 | 需第三方补 | 全 |
| 大列表 / 高刷滚动 | 一般,需优化 | 好 |

也就是说:

- 目标是「看起来像 Win11 原生小工具」→ **WPF + WPF-UI 足够**,性价比最高。
- 目标是「和系统设置页一模一样、动画丝滑」→ 才值得上 WinUI 3,但要接受绿色分发的折腾。
- 目标是「完全自定义视觉、像 Web 应用」→ 可考虑 Avalonia,或在个别页面嵌 WebView2(会增加依赖,不建议整体走这条路)。

### 首版就定死的视觉规范

1. WPF-UI 4.x 作为唯一 UI 库,不叠加其他主题库。
2. `FluentWindow` + Mica,Win10 自动降级纯色。
3. 自定义标题栏 + 左侧 `NavigationView`,右侧内容区留白 24px。
4. 设计 token 全部走资源字典,禁止页面里写死颜色/字号。
5. 只做三类动效:页面切换、Snackbar、骨架加载。
6. 验收环境:Win10 22H2、Win11 23H2+、中文 IME、125% / 150% 缩放。

## 5. 免安装(绿色版)策略

### 5.1 两种产物,同一份代码

| 产物 | 形态 | 优点 | 缺点 | 用途 |
|---|---|---|---|---|
| **A. 目录绿色版(主推)** | zip,解压到任意目录 | 启动最快、可增量替换、杀软误报少 | 文件多 | 日常使用、内部分发 |
| **B. 单文件 exe** | 单个 exe | 拷贝方便 | 首次启动解压到 `%TEMP%`,略慢;易被误报 | 临时救急、发给别人 |

### 5.2 发布命令

目录版(主推):

```powershell
dotnet publish src/Seeker.DevToolbox.App/Seeker.DevToolbox.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=false `
  -p:DebugType=None -p:DebugSymbols=false `
  -o publish/portable
```

单文件版:

```powershell
dotnet publish src/Seeker.DevToolbox.App/Seeker.DevToolbox.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -p:DebugType=None -p:DebugSymbols=false `
  -o publish/single
```

注意事项:

- **不要开 `PublishTrimmed`**。WPF 不支持裁剪,开了会在运行期出现反射/资源缺失。
- `EnableCompressionInSingleFile` 能把包压到约 60–70MB,代价是首启再慢一点。
- 自包含包不需要目标机安装 .NET;仅要求 Win10 1607+(实际按 Win10 22H2 / Win11 验证)。
- 发布脚本里顺手生成 `SHA256SUMS.txt`,方便分发校验。

### 5.3 数据目录与「真·绿色」判定

```csharp
public static string ResolveDataRoot()
{
    var exeDir = AppContext.BaseDirectory;

    // 存在 portable.marker 即进入便携模式:数据全部留在程序目录
    if (File.Exists(Path.Combine(exeDir, "portable.marker")))
        return Path.Combine(exeDir, "data");

    return Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
        "Seeker", "DevToolbox");
}
```

规则:

- 便携模式下设置、日志、缓存、插件、临时文件全部在 `data/` 下,拷走目录即迁移。
- 安装到只读位置(如 `Program Files`)时,检测写权限失败 → 自动回退到 `%LOCALAPPDATA%`,并在设置页提示。
- **绝不写注册表**;文件关联、开机自启作为显式可选项(默认关闭),且提供一键还原。
- 卸载 = 删除目录(+ 可选删除 `%LOCALAPPDATA%` 残留)。

### 5.4 分发时的现实问题

- **SmartScreen / Defender**:未签名的自包含 exe 首次运行大概率被拦。对策:① 主推 zip 分发并附校验值;② 条件允许时买代码签名证书(EV/OV,约 200–400 美元/年);③ 在 README 写清拦截原因和解锁步骤。
- 单文件 exe 每次启动会释放到 `%TEMP%\.net\...`,部分企业管控环境会拦截,这也是主推目录版的原因之一。

## 6. 应用架构

### 6.1 分层原则

**核心逻辑与 UI 解耦**:所有转换/解析/校验逻辑放 Core,不引用 WPF,保证可单测、未来可迁 Avalonia 或做 CLI。

### 6.2 目录结构

```
seeker-dev_tool/
├─ src/
│  ├─ Seeker.DevToolbox.App/          # WPF 宿主:启动、导航、主题、DI、单实例
│  ├─ Seeker.DevToolbox.Core/         # 纯逻辑:格式化/转换/解析/校验(无 UI 依赖)
│  ├─ Seeker.DevToolbox.UI/           # 通用控件、ViewModel 基类、主题资源
│  └─ Seeker.DevToolbox.Tools/        # 各工具模块(按功能分子目录)
├─ tests/
│  └─ Seeker.DevToolbox.Core.Tests/
├─ build/
│  ├─ publish.ps1                     # 发布两种产物
│  └─ package.ps1                     # 打 zip + 校验值
├─ docs/
└─ Seeker.DevToolbox.sln
```

### 6.3 工具模块契约

```csharp
public sealed record ToolMetadata(
    string Id,
    string Title,
    string Category,
    string Glyph,        // Segoe Fluent Icons 字形
    string[] Keywords);  // 搜索别名,如 "json,格式化,beautify"

public interface IToolModule
{
    ToolMetadata Metadata { get; }
    FrameworkElement CreateView(IServiceProvider services);
}
```

- MVP 阶段:在 `Tools` 程序集内用**显式注册表**列出模块,启动时批量注册到 DI,简单可预测。
- 演进阶段:扫描 `data/plugins/*.dll`,用 `AssemblyLoadContext` 隔离加载,契约版本号写进接口,避免插件间依赖冲突。
- 每个工具 = 一个 `UserControl` + 一个 ViewModel,共享 `IToolModule` 外壳,便于统一「复制结果 / 清空 / 示例 / 快捷键」。

### 6.4 主窗口布局

```
┌──────────────────────────────────────────────┐
│ 自定义标题栏  [搜索工具…]        ─  □  ×      │
├──────────┬───────────────────────────────────┤
│ 分类导航  │  工具内容区                        │
│ ▸ 常用    │  ┌─────────────────────────────┐  │
│ ▸ 编码    │  │ 输入区(编辑器)              │  │
│ ▸ 文本    │  ├─────────────────────────────┤  │
│ ▸ 网络    │  │ 输出区 / 操作按钮            │  │
│ ▸ 系统    │  └─────────────────────────────┘  │
├──────────┴───────────────────────────────────┤
│ 状态栏: 字符数 / 耗时 / 错误提示              │
└──────────────────────────────────────────────┘
```

- 顶部搜索框支持按标题、分类、关键词模糊匹配,回车直达(为后续「命令面板」留接口)。
- 「最近使用」置顶,最多 8 个。
- 大文本处理:输入防抖 300ms + 后台线程 + 结果版本号丢弃过期计算。

### 6.5 启动流程

1. 单实例检查(Mutex);已存在则通过命名管道把参数发给主实例并退出。
2. 解析数据目录 → 初始化日志 → 加载 `settings.json`(失败则用默认值并备份坏文件)。
3. 注册 DI 与工具模块 → 应用主题(跟随系统/深色/浅色)。
4. 全局异常钩子(`DispatcherUnhandledException` + `AppDomain.UnhandledException` + `TaskScheduler`),写日志并弹可复制的错误窗。
5. 显示主窗口。

## 8. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 单文件首启慢 / 杀软误报 | 体验与分发受阻 | 主推目录绿色版;单文件仅作备选;附 SHA256 |
| WPF 观感偏旧 | 产品力不足 | .NET 10 内置 Fluent 主题 + WPF-UI + 自定义标题栏 + Mica;首版就定视觉规范(§4.1) |
| 大文本卡顿 | 核心场景翻车 | AvalonEdit 虚拟化;计算放后台;防抖 + 结果版本号;限制预览长度 |
| 自包含包 150MB | 下载/拷贝慢 | 可接受;zip 压缩后约 60–70MB;后续可评估 Avalonia + NativeAOT |
| 插件 DLL 冲突 | 启动崩溃 | AssemblyLoadContext 隔离 + 契约版本号;插件异常降级为「该工具不可用」 |
| 中文/IME 输入异常 | 编辑器不可用 | AvalonEdit 成熟;早期就在 Win10/11 中文环境做 IME 回归 |
| 数据写不进去(只读目录) | 启动失败 | 写权限探测 + 自动回退 `%LOCALAPPDATA%` + 提示 |
| 未签名被 SmartScreen 拦 | 用户不敢用 | 文档说明 + 校验值;有条件则签名 |
